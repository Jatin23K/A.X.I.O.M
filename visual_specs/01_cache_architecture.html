AXIOM Blueprint — 01 Cache Architecture

Building & Fetching Multi-Tier Semantic Cache (Text, Image pHash/CLIP, Video & Audio)

Sub-15ms Latency Redis Stack Vector In-Memory allkeys-lru Eviction
⚡ 30-Second Elevator Pitch (What to say when asked "How does AXIOM's Caching work?")
"AXIOM uses a zero-redundancy two-tier caching pipeline powered by Redis Stack. Incoming queries pass through Input Guardrails first, followed by a Tier 0 SHA-256 exact string match (< 1ms). If that misses, we slice a 128-dim Matryoshka vector from a single forward pass to run Tier 1 cosine similarity search (>= 0.92) in RAM (~15ms). For images and media, we use pHash Hamming distance (<= 4) and CLIP vectors. On a cache hit, we bypass Qdrant and the LLM entirely, saving 99% in latency and 100% in API cost."

2. 3-Tier Multi-Modal Cache Stores

1. Text Cache Store (Namespace: cache:text)
Caches conversational text, document RAG, and SQL queries.
  • Tier 0 Exact String Match: Normalized string SHA-256 hash lookup in Redis RAM (< 0.2ms).
  • Tier 1 Semantic Vector Match: Matryoshka 128-dim vector slice cosine similarity (>= 0.92) in Redis Stack (~15ms).
  • Zero-Redundancy Vector Reuse: Generates embedding vector ONCE. Slices 128-dim for cache; reuses full 1536-dim for Qdrant on cache MISS.
2. Image Cache Store (Namespace: cache:image)
Caches photo uploads, infographics, and cropped diagrams.
  • Tier 0 Perceptual Hash (pHash): Hashes $8 \times 8$ pixel brightness gradients. Matches identical or cropped/resized photos via Hamming Distance $\le 4$ in < 1ms.
  • Tier 1 Visual CLIP Vector Match: 512-dim CLIP visual embedding cosine similarity (>= 0.90) for different angles/lighting in ~20ms.
3. Video & Audio Cache Store (Namespace: cache:multimodal)
Caches MP4 videos, speech voice notes, and audio streams.
  • Audio Cache: Chromaprint acoustic waveform fingerprinting (Hamming $\le 2$, < 2ms) + Whisper transcript Matryoshka vector.
  • Video Cache: Keyframe sequence `pHash` (1 frame/sec, mean Hamming $\le 3$, < 5ms) + Whisper transcript alignment.

3. Cache Creation Write Flow & Eviction Strategy

Cache Creation (Write Flow on Cache MISS)

Cache entries are written ONLY AFTER Output Guardrails pass validation. This guarantees that every entry in Redis is pre-sanitized, allowing future Cache HITs to safely skip Output Guardrails.

# Production Redis Write Pattern
redis_client.hset(
    name=f"cache:text:{hash(query_text)}",
    mapping={
        "query_text": query_text.lower().strip(),
        "query_vector": v_128.tobytes(),  # 128-dim Matryoshka vector
        "answer_payload": clean_verified_answer,
        "created_at": time.time()
    }
)
redis_client.expire(f"cache:text:{hash(query_text)}", 86400) # 24h TTL
Memory Limit & Eviction Policy (maxmemory allkeys-lru)

FIFO is rejected because it evicts popular queries. We use allkeys-lru (Least Recently Used) + 24-hour TTL expiration.

# redis.conf Mandatory Production Config
maxmemory 4gb
maxmemory-policy allkeys-lru

4. Interview Q&A Defense for Caching

Q1: Do you call the embedding model twice on a Cache MISS?

No, never. We call the Matryoshka embedding model exactly ONCE after Input Guardrails pass. The model outputs a 1536-dim vector. We slice `vector[:128]` in 0 microseconds to check the Redis cache. If the cache misses, we take the exact same 1536-dim vector object already in memory and pass it directly to Qdrant. Zero re-embedding overhead.

Q2: Why do you skip Output Guardrails on a Cache HIT?

Because cache entries are written only after passing Output Guardrails during their initial Cache MISS execution. Every response stored in Redis is pre-sanitized and verified. Skipping Output Guardrails on Cache HIT allows us to serve responses in sub-15ms.

Q3: Why use pHash for images instead of running CLIP for everything?

pHash is pure bitwise CPU math executing in < 1ms. It matches identical, cropped, or resized photos without running a neural network. CLIP requires a forward pass (~20ms). By chaining pHash (Tier 0) before CLIP (Tier 1), we handle 80% of duplicate image uploads instantly without touching the GPU.
