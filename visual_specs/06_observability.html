A.X.I.O.M — 06 Production Observability & RAG Triad

RAG Triad Metrics · OpenTelemetry Tracing · Safe Failure Contract · Verbatim Citation Mapping
30-Second Pitch: In production RAG systems, a confident wrong answer is more dangerous than no answer. A.X.I.O.M. enforces a zero-hallucination guarantee through 3 mechanisms: the RAG Triad (mathematical quality scoring on every response), the Safe Failure Contract (blocking LLM generation when context is insufficient), and the Verbatim Citation Mapping Engine (every claim tagged with [Ref X] pointing to an exact source page, audio timestamp, or video frame). All 3 mechanisms run through an OpenTelemetry distributed tracing layer that logs per-step latency, token cost, and quality scores to an AI Ops dashboard — without adding any synchronous latency to the user response.

The RAG Triad (3 Quality Metrics)

Metric 1 — Context Relevance (Retrieval Precision)

  • Question: Did Qdrant retrieve chunks that actually answer the user's query?
  • Formula: Context_Relevance = Relevant_Chunks_Retrieved / Total_Chunks_Retrieved
  • Target: > 0.70 | Safe Failure Threshold: < 0.40
  • Failure Mode: Returns irrelevant document sections (Qdrant tuning issue)

Metric 2 — Groundedness / Faithfulness (Hallucination Prevention)

  • Question: Is every claim in the generated answer supported by verbatim text in the retrieved context?
  • Formula: Groundedness = LLM_Claims_Backed_by_Context / Total_LLM_Claims
  • Target: 1.00 (100% — zero tolerance for unbacked claims)
  • Failure Mode: LLM invents specific numbers, dates, or names not in context

Metric 3 — Answer Relevance (Intent Alignment)

  • Question: Does the generated answer directly address the user's original intent?
  • Formula: Answer_Relevance = Cosine_Similarity(Query_Vector, Answer_Vector)
  • Target: >= 0.85
  • Failure Mode: Answer is grounded but drifts off-topic from the original question

Safe Failure Contract

The 3 Safe Failure Triggers

  1. Context Relevance < 0.40:
    • Action: Block LLM call entirely
    • Response: 'I cannot find sufficient verified information to answer this safely. Please contact [department contact] or [IT ticket URL].'
    • Telemetry: Log query to 'Knowledge Gap Dashboard' for documentation team action
  2. Groundedness < 1.00:
    • Action: Strip unbacked claims from response before serving
    • Response: Partial answer with banner: 'Some claims could not be verified against source documents and have been removed.'
    • Telemetry: Flag specific unbacked claim text for LLM temperature tuning
  3. Circuit Breaker OPEN (LLM API Down):
    • Action: Route to fallback model (Flash → Ollama)
    • Response: Answer generated by fallback model with banner: 'Response generated by local fallback model.'
    • Never returns HTTP 500 to user

Knowledge Gap Detection Loop

  • Every Safe Failure (Context Relevance < 0.40) is logged to AI Ops dashboard
  • Documentation team reviews weekly: 'Top 10 unanswerable queries this week'
  • Each entry represents a missing document that should be uploaded to A.X.I.O.M.
