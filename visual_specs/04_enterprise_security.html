A.X.I.O.M — 04 Enterprise Security & RBAC

JWT API Gateway · 2-Checkpoint Security · Role-Scoped Cache Isolation · Zero-Trust Access

Section 0: 30-Second Pitch

A.X.I.O.M. enforces a Zero-Trust security model across two independent checkpoints. Checkpoint 1 (API Gateway) validates JWT bearer tokens in under 0.5ms and blocks unauthorized route access before touching any database. Checkpoint 2 (Qdrant Pre-Filter) enforces document-level access by filtering vector search to only records matching the user's clearance level and department — before any cosine similarity calculation runs. The Cache layer is secured by Role-Scoped Cache Keys that cryptographically bind query results to the exact Permission Set of the user who generated them.

Section 1: The 2-Checkpoint Security System

HTTP REQUEST (Bearer JWT Token)
  │
  ▼
[ CHECKPOINT 1: API Gateway (<0.5ms) ]
  │ Validates JWT signature using OIDC Public Key (JWKS) from RAM
  │ Decodes: user_id, tenant_id, department, rbac_roles, clearance_level
  │ Checks: user_clearance >= route_required_clearance
  │
  ├──► FAIL → HTTP 401 (Invalid/Expired Token) | HTTP 403 (Insufficient Clearance)
  ▼ PASS
[ ROLE-SCOPED CACHE CHECK ]
  │ Key: SHA256(Tenant_ID + Department + Clearance_Level + Query_Text)
  │
  ├──► HIT → Return cached answer (Guaranteed authorized for this clearance)
  ▼ MISS
[ CHECKPOINT 2: QDRANT PRE-FILTER (<20ms) ]
  │ Filter: required_clearance <= user_clearance
  │       AND is_active_version == true
  │       AND department_id IN user_departments
  │ Vector search runs ONLY on pre-filtered authorized subset
  │
  └──► Returns only documents user is authorized to access

Section 2: JWT Token Lifecycle

  • Issuance: When an employee logs in via Okta/Keycloak, a signed JWT is issued containing: user_id, tenant_id, department, rbac_roles[], clearance_level, exp (expiration timestamp)
  • Expiration: Token expires after 15-60 minutes (exp timestamp). API Gateway rejects expired tokens with HTTP 401.
  • Revocation (Fired Employee): IT Admin disables account → Refresh Token revoked → JWT token ID (jti) added to Redis Token Blacklist → Gateway checks blacklist on every request. Sub-1ms block.
  • Zero Database Calls: All user claims are embedded in the JWT. Gateway verifies using cached JWKS public key in RAM. No SQL queries on every request.

Section 3: Clearance Level Hierarchy (4 Levels)

Level 0: PUBLIC      → Office address, holiday schedule, Wi-Fi password
Level 1: INTERNAL    → Project specs, team roadmaps, engineering docs
Level 2: RESTRICTED  → Executive salaries, Q3 financial reports, layoff plans
Level 3: ADMIN       → System configs, API keys, infrastructure access
  • Level N users can access Level N and all levels BELOW (inheritance).
  • Cache keys embed clearance level: A Level 2 user CAN hit a Level 0 or Level 1 cache entry.
  • A Level 1 user CANNOT hit a Level 2 cache entry — the key strings are cryptographically different.

Section 4: Role-Scoped Cache Key Architecture

The Formula

Cache_Key = SHA256(Tenant_ID + Department + 'LEVEL_' + Clearance_Level + Normalized_Query)

Why this prevents breaches (scenario walkthrough)
  • Manager (LEVEL_2, DEPT: FINANCE) asks 'What is the executive bonus structure?'
    → Key: SHA256('CORP_01:FINANCE:LEVEL_2:executive bonus') → key_999X
    → Stored in Redis under key_999X
  • Employee (LEVEL_1, DEPT: FINANCE) asks EXACT same question
    → Key: SHA256('CORP_01:FINANCE:LEVEL_1:executive bonus') → key_111Y
    → key_111Y ≠ key_999X → CACHE MISS → Qdrant Pre-Filter blocks Level 2 docs
    → Employee safely receives 'Access Denied'
Three Cache Security Modes
  • 1. PERMISSION-SET HASH: Different roles = Different cache namespace (default)
  • 2. DOCUMENT ACL CHECK: Cache write stores source_doc_ids; future users must have access to all source docs
  • 3. cacheable: false FLAG: Sensitive documents tagged to never be written to Redis cache

Section 6: Why Pre-Filtering Beats Post-Filtering (Critical Design Decision)

  • POST-FILTERING (WRONG): Run vector search on ALL 1,000,000 records → Get Top-10 → Strip unauthorized results → May return only 1-2 useful chunks → RAG context is broken
  • PRE-FILTERING (AXIOM STANDARD): Apply RBAC metadata filter BEFORE cosine similarity → Vector search runs only on authorized subset → Every Top-K result is guaranteed authorized → RAG context is always complete
