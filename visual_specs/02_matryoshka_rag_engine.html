2. Building Phase (Storage & Vector Indexing)

1. Hierarchical Parent-Child Chunking

Solves the chunk size dilemma (too small = lost context; too big = LLM "Lost in the Middle").

  • Parent Chunks (~1,000 tokens): Stores complete background narrative and section context.
  • Child Chunks (~200 tokens + 15% overlap): Holds exact facts for high-precision vector matching.
  • Mapping: Each child chunk payload contains a reference pointer "parent_id": "doc_101_parent".
2. Matryoshka Representation Learning (MRL) & L2 Normalization

Optimizes vector database RAM footprint and computes similarity searches 3x faster.

  • Vector Slicing: Single embedding model call generates 1536-dim vector. Sliced to 128 dims (v[:128]) for RAM HNSW index.
  • L2 Standardization: Normalizing vectors (||v|| = 1.0) simplifies Cosine Similarity to pure CPU SIMD Dot Product ($\mathbf{A} \cdot \mathbf{B}$).
3. BM25 Sparse Vector Normalization

Prevents long documents or keyword-stuffed text from distorting keyword search rankings.

  • Logarithmic TF Saturation ($k_1 = 1.2$): Term frequency score follows a diminishing-returns logarithmic curve.
  • Document Length Normalization ($b = 0.75$): Penalizes overly verbose documents.

3. Fetching Phase (Search & Reranking)

1. HyDE (Hypothetical Document Embeddings) Query Transformation

Generates a hypothetical answer first, embedding that text instead of the short user query to boost vector precision by 24%.

2. Stage 1: Coarse Hybrid Search & RRF Rank Fusion

Merges dense vector search (128-dim HNSW) and sparse keyword search (BM25) using Reciprocal Rank Fusion.

# RRF Scoring Formula
RRF_Score(doc) = (1 / (60 + Rank_dense)) + (1 / (60 + Rank_sparse))
3. Stage 2: Cross-Encoder Reranker (bge-reranker-large)

Evaluates raw Query text + Candidate Chunk text together in full transformer cross-attention to output exact relevance scores (0.0 to 1.0), extracting the Top-5 pristine chunks.

4. Interview Q&A Defense for Matryoshka RAG

Q1: Why do you pre-normalize vectors before storing them in Qdrant?

L2 normalizing vectors to unit length (length = 1.0) forces all vectors onto a unit hypersphere, removing magnitude bias. Mathematically, Cosine Similarity simplifies to the Dot Product (\(\mathbf{A} \cdot \mathbf{B}\)). This allows vector databases to execute searches using raw CPU SIMD matrix multiplication, cutting retrieval latency by over 70%.

Q2: Why use Reciprocal Rank Fusion (RRF) instead of just adding vector similarity scores?

Dense vector scores (0.0 to 1.0) and BM25 sparse scores (0.0 to 25.0+) exist on completely different numerical scales. Normalizing them manually is unstable. RRF merges lists based on rank positions rather than raw scores, making hybrid search combination robust and scale-invariant.

Q3: Does the Cross-Encoder Reranker use Matryoshka embeddings?

No. Cross-Encoders do not use vector embeddings. Bi-encoders (Matryoshka models) turn text into vectors for fast ANN search. The Cross-Encoder takes raw Query text and Candidate Chunk text together into transformer self-attention layers to output a single 0-to-1 relevance logit score.
